1 · System overview (HLD)

Two features shipped this cycle: backend-owned authentication (Google login → JWT) and Profile Builder — GitHub slice (link GitHub, collect data, render a descriptive profile). The frontend is a thin Bearer-token client; the Spring backend owns all OAuth handshakes, persistence, and data collection.

The access token never leaves JS memory; persistence across reloads is the httpOnly refresh cookie + a silent refresh on load.

3 · Login flow — "Path A" (backend-owned)

Google login is run entirely by Spring. The frontend just kicks it off and later exchanges the refresh cookie for an in-memory access token.

4 · GitHub connect flow (Profile Builder)

A second, separate OAuth flow for account linking (not login). The key subtlety: the authorize step needs the user's identity, but a browser navigation cannot carry the in-memory Bearer token — so we fetch the URL with the token, then navigate.

sequenceDiagram autonumber participant U as Browser participant FE as Connections participant BE as Backend participant GH as GitHub participant DB as Postgres U->>FE: click Connect GitHub FE->>BE: apiFetch GET authorize, Bearer header BE->>BE: jwt subject to userId, sign HMAC state BE-->>FE: 200 JSON with github authorize url FE->>U: window location to github url U->>GH: consent, scope read user GH-->>U: redirect to callback with code and state U->>BE: hit callback, no JWT, permitAll BE->>BE: verify state to userId, CSRF plus identity BE->>GH: exchange code for access token BE->>GH: GET user to read login BE->>BE: TokenCipher encrypt token BE->>GH: GraphQL viewer, contributions, repos, PRs BE->>BE: normalize fragment, SHA-256 canonical hash BE->>DB: upsert github connection and profile fragment jsonb BE-->>U: redirect to frontend connections U->>FE: refetch profile me, render profile

profile_fragment is deliberately source-agnostic (one row per user+source) so adding Résumé/LeetCode later is a new collector, not a schema change. content_hash drives idempotent re-fetch (skip write when data unchanged).

8 · Decisions & the paths we did not take

Each card: what we chose (✓), why, and the alternatives we rejected.

ADR-01 · Auth ownership security

✓ Path A — backend owns the Google OAuth handshake; frontend is a thin Bearer client.

Why: the Spring backend was already built & committed doing exactly this; it keeps OAuth secrets server-side and gives one auth model for all clients.

Rejected — Path B (NextAuth/Auth.js on the frontend): the scaffold assumed it, but it would mean two systems trying to own the Google handshake and rewriting the working backend. Removed NextAuth entirely.

ADR-02 · Access-token storage frontend

✓ In-memory + silent refresh (token in a JS module var; refresh cookie restores it).

Why: not readable by XSS; pairs with the httpOnly refresh cookie.

Rejected — localStorage: survives reloads but is XSS-readable.

ADR-03 · Route gating frontend

✓ Client-side RequireAuth guard wrapping the (app) shell.

Why: the in-memory token and the path-scoped refresh cookie are invisible to Next middleware, so server-side gating can't see auth state.

Rejected: Next middleware auth() (can't read the token); widening the cookie path to / (leaks the refresh cookie to every route).

ADR-04 · GitHub data access security

✓ Per-user GitHub OAuth, scope read:user, token encrypted at rest.

Why: gets the contribution graph + external PRs; minimal scope = least-scary consent and smallest breach radius.

Rejected: a single app-token + pasted username (no private data, but we chose real OAuth); repo scope (full private-code read — overkill); public REST only (loses the contribution graph).

ADR-05 · GitHub token at rest security

✓ AES-256-GCM, key in env (GITHUB_TOKEN_KEY).

Why: reversible (we must replay it to GitHub), authenticated encryption, pragmatic pre-revenue.

Rejected: cloud KMS/Vault (infra we don't have yet — noted as the prod upgrade path); fetch-then-discard (no background refresh possible).

ADR-06 · Profile Builder scope product

✓ First slice = connect → collect → render raw, descriptively (no LLM).

Why: the LLM synthesis prompt is flagged product-IP and the Python synthesis service doesn't exist; a rule-based assembler is a swappable stand-in.

Rejected: full pipeline incl. the LLM (blocked on IP + a missing service); backend-only (no value to see).

ADR-07 · "How good an engineer" framing product

✓ Convey strength via evidence density — notable highlights + cross-source skill evidence.

Why: CLAUDE.md hard rule: no scoring/ranking/grades ever. "412 solved (268 Medium)" not "above-average".

Rejected: any score/rank/tier badge.

ADR-08 · Consolidated profile layout UX

✓ Layout A — highlights band + source-card grid (chosen visually).

Why: a cross-source "Notable" band conveys strength; grid scales as sources are added (one card each).

Rejected: Layout B — single narrative column (closer to the eventual LLM narrative field, kept in mind for later).

ADR-09 · App shell frontend

✓ Cherry-pick the dashboard-01 shell (sidebar+header+nav) into (app)/layout.tsx.

Why: battle-tested shell, while skipping the demo DataTable's @dnd-kit/react-table deps (CLAUDE.md "ruthless on complexity").

Rejected: install the whole block (5 unused deps); build a sidebar from scratch.

ADR-10 · shadcn CLI version tooling

✓ Classic shadcn@2.10.0 (Radix + Tailwind-3, HSL tokens).

Why: the latest shadcn@4.x is the new Tailwind-4-centric "platform" CLI; it would clash with this Tailwind-3 + HSL-token repo. The classic CLI added Tailwind-3 sidebar/chart tokens natively.

Rejected: shadcn@latest (4.10) — risked clobbering tokens / assuming Tailwind 4.

ADR-11 · JSONB persistence backend

✓ Store fragment as a String in a jsonb column + stringtype=unspecified so Postgres casts the bind param.

Why: deterministic bytes for hashing; avoids Hibernate-7-vs-Jackson-3 JSON-mapper friction. The driver flag fixes the varchar→jsonb cast (see Bug-03).

Rejected: @JdbcTypeCode(SqlTypes.JSON) on the String (risky with Jackson 3's FormatMapper); plain text column (loses jsonb + needs a column-type migration).

ADR-12 · GitHub authorize transport bugfix

✓ authorize returns the URL as JSON; frontend apiFetches it (Bearer) then navigates.

Why: a top-level browser navigation can't carry the in-memory Bearer token (see Bug-02). Fetching keeps the token in a header and gains 401-refresh.

Rejected: 302-redirect from authorize (the original — broke because the nav had no JWT); token in a query param (leaks into history/logs).

ADR-13 · Design system UI

✓ Geist (strict): Geist Sans/Mono fonts + neutral tokens + shadcn.

Why: "Vercel aesthetic" realized concretely; shadcn IS the Geist component layer for React.

Rejected: the community @geist-ui/core library (unofficial port, would rewrite everything); keeping Inter + slate.

ADR-14 · Where the slice lives arch

✓ Inside the existing single interviewiq-backend.

Why: pre-revenue discipline; the documented polyrepo split isn't realized.

Rejected: a new interviewiq-api service; porting the older Go prototype's handlers.

10 · Bugs we hit & the fixes

Bug-01 · Backend won't start env

Symptom: SocketTimeoutException → EntityManagerFactory fails at boot.

Root cause: Supabase Postgres unreachable on :5432 (project paused / port path). Not a code bug — ddl-auto=update needs a live DB at startup.

Fix: DB became reachable again; verified with psql select 1. (Also surfaced the JDK-25 JAVA_HOME requirement.)

Bug-02 · GitHub connect → 500 NPE auth

Symptom: jwt.getSubject() NPE in authorize().

Root cause: "Connect" did a full-page window.location nav to /authorize, which can't carry the in-memory Bearer token → no JWT principal (it only reached the controller because a leftover oauth2Login session was an OAuth2User, not a Jwt).

Fix: authorize returns JSON; frontend apiFetches it (Bearer header) then navigates (ADR-12) + null-guards the principal (401).

Bug-03 · Connect fails silently db

Symptom: ?error=github_connect_failed; the callback swallowed the exception (no log).

Root cause: column "data" is of type jsonb but expression is of type character varying — the String field bound as varchar; Postgres won't implicitly cast varchar→jsonb on insert.

Fix: (1) log the swallowed exception; (2) stringtype=unspecified so the driver lets Postgres cast String params to jsonb (ADR-11).
